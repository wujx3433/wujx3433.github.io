# 27 Nov 2026 我花一百块钱收了个不省心的控制器

众所周知，Zn我最近经营着音游窝，在经营之余，我经常淘一点和音游有关的小垃圾回来。

这次，我就在小黄鱼上看到了一个非常神奇的好东西：一个只要一百块钱就能到手的 Project DIVA 风格控制器。

这岂不是相当于白送嘛，于是立即支付，即可下单。

此时的Z师傅还不知道，自己究竟是请了怎么样一个活爹回来。

![](/小黄鱼-初音手台.jpg)

## 一、开箱：一台"初音天使"

东西到手，型号是 **ipega PG-P4016**，官方叫「初音天使游戏控制器」。

外观确实唬人：四个大键按街机配色——三角绿、方框粉、叉蓝、圈红；上方一条触摸滑条，左右各有一个 3D 摇杆区，肩键、扳机、share/options/HOME 一应俱全。摇杆下面还有个小支架，可以立 Switch。

不过得说清楚，这是台**丐中丐的小台**——尺寸大概只有街机面板的一半，按键也小一圈。想要全尺寸的话，要么去淘 HORI 那台，要么上鸽屋 DJDAO 的 DIVALLER，那就不是一百块能解决的事了。

![](/初音手台外观.jpg)

插上 Mac，系统认出来一个叫 `Wire PS4 Controller` 的东西，VID:PID 是 `2563:0119`。

当时我心里还挺美：DS4 协议，那不就随便折腾了？事实证明，这个"随便"二字，是我今晚一切噩梦的开端。

## 二、第一折腾：官方软件连不上

按照惯例，先找官方资料。产品页上除了一个说明书 PDF，什么都没有——没有下载中心，没有配置工具，没有固件。

好不容易从别的渠道搞到两个官方刷机包：

- `BM-946-V8-4016_202104281428.exe`（P4 版）
- `SW056_V3.exe`（Switch 版）

在 Windows 上一跑，不出意外地出了意外：

```
USB Connect Fail!
```

一开始我以为是驱动问题、权限问题、线的问题，折腾了半天。直到我把这个 exe 拆开反汇编，看到这么一段：

```asm
mov  eax, 0x416
cmp  word ptr [ebp-0x13c], ax   ; VendorID 必须等于 0x0416
jne  0x403ca0                   ; 不是就跳过这个设备
```

`0x0416` 是新唐科技（Nuvoton）的厂商 ID。配套的 PID 是 `0x3F00`。而这台手台的 bootloader 报出来的是 `0x2F81:0x7209`，名字叫 `ShanWan Update`——山湾自己的东西。

两个 exe 里还留着 `There is no Nu-Link connected to a USB port.` 这种字符串，`Nu-Link` 是新唐的官方调试器，PDB 路径写着 `F:\work\USB_ISP_TOOL\BM-946\...\DFUTools.pdb`。

**结论**：这工具是拿新唐的 ISP 工具改的 UI，只认新唐原厂 ISP 模式；而我手上这台，bootloader 是山湾自研的。两者永远不会握手。

更微妙的是三个编号对不上：丝印是 `BM-947`，固件是 `BM-946`，bootloader 序列号是 `P4-BM-945`。三个数字，三个修订版本，说明这条产线至少改过三次硬件，而工具只跟得上其中一版。

![](/初音手台主控.jpg)

## 三、拆开它自带的固件

虽然刷不进去，但工具里**自带固件**——资源段里躺着一个 38512 字节的 `BM_0575`，开头就是 Cortex-M 的向量表：

```
f8 1e 00 20   → 栈顶 0x20001EF8
f1 00 00 00   → 复位向量 0x000000F1
```

把这份固件翻开来，发现了整晚最有趣的东西：里面塞了**五套 USB 设备描述符**。

| 模式 | VID:PID | 会被认成 |
|---|---|---|
| 0 | `2563:0119` | Wire PS4 Controller（就是我现在这个） |
| 1 | `2563:0575` | 山湾自有 |
| 2 | `045E:028E` | **微软 Xbox 360 手柄** |
| 3 | `2563:0526` | 山湾自有 |
| 4 | `057E:2009` | **任天堂 Switch Pro 手柄** |

字符串表里还有 `QIXIONG`、`Nintendo Co., Ltd.`、`Xbox360 For Windows`、`Pro Controller`。

看到这里我眼睛都亮了：**这不是可以切成 Xbox 模式吗？** 切过去 Windows 直接认成原生 XInput，还要什么驱动？

于是我满怀期待地试了各种组合键：`HOME + □`、`HOME + ×`、`HOME + ○`、`HOME + △`，后来连"只按四个大键不按 HOME"都试了。结果很干净——**一个新模式都没出现**，只会在 `2563:0119` 和 bootloader 之间来回。

回头再翻固件代码，答案写在那儿：那张模式表有 5 个条目，但代码从头到尾只引用了第 0 项。**模式是编译期写死的，运行时根本不可切换。** 另外四个描述符是两家共用代码库留下的尸体。

顺带还发现，固件里的 HID 描述符和我实机读到的描述符，一致率 97.7%——同一产品线，不同修订。

## 四、那些"看起来能用"的接口

在放弃之前，我还试了几条看起来很有希望的路。

**厂商 Feature 接口。** 设备除了手柄接口，还有一个 Usage Page 为 `0xFFF0` 的厂商接口，挂着四个 Feature 报告。其中 `0xF1` 特别可疑——它是 60 字节数据 + 4 字节尾巴，而那 4 字节正好是前 60 字节的 CRC32：

```
[0xF1][序号][58 字节数据][crc32(前 60 字节)]
```

带校验的配置块！我一度以为找到了改键通道。结果连续抓了 300 帧后发现：序号是滚动计数，但**同一个序号在两轮里内容完全不同**，拔插之后也对不上。也就是说它根本不是可寻址的内存或配置，只是一个没实现的信箱，返回的是缓冲区里的残留。

**机身那个 Type-C 公头。** 这台机器前面板伸出一个公口 Type-C，形状一看就是给 Switch 底部用的。

这里得澄清一下：ipega 确实有**能直连 Switch 的版本**，那个版本的同位置公口是完整工作的，插上 Switch 就会被识别成手柄——当然二手价也贵，要两三百。

而我手上这台是 P4 版，同一个模具、同一个位置，公口是个残废。万用表一量：CC1 对地 5.1kΩ，CC2 对地开路，上电后那两根线是 5V——**只有 VBUS 和 GND，根本没有 D+/D-**。

一个能用一个不能用，差价一百多。这也算是「丐中丐」的一部分。

## 五、真正的收获：把报文拆干净

折腾到这里，固件层是彻底没戏了。但前面那一堆失败，反而逼着我把它**报文层**摸了个底朝天。

64 字节，Report ID `0x01`，和 DualShock 4 有线报文同构。逐字节扒下来是这样的：

| 偏移 | 内容 |
|---|---|
| 1–4 | X / Y / Z / Rz（摇杆或滑条） |
| 5 | 十字键 + 按键 1–4 |
| 6 | 按键 5–12 |
| 7 | 按键 13–14 + 6 位滚动计数器 |
| 8–9 | Rx / Ry：L2 / R2 的模拟量 |
| 35–42 | 两个触摸点，DS4 格式 |

按键位是：

- bit 1–4：方框 / 叉 / 圈 / 三角
- bit 5–8：L1 / R1 / L2 / R2
- bit 9–10：share / options
- bit 13：HOME
- bit 14：触摸板按压

有两个细节让我印象深刻。

**第一，扳机是模拟的。** L2/R2 不只是数字位，还各自驱动 Rx/Ry 两个轴，0–255。这解释了描述符里那两轴为什么存在——那是 DS4 报文里扳机的原位置，山寨厂照抄了。

**第二，触摸板是真 DS4 格式。** 报文 35–42 字节是两个触点，每点 4 字节：

```
[bit7=未触摸][id][X 低 8][X 高 4 | Y 低 4][Y 高 8]
```

分辨率 1920×960，静止时读 `1919, 959`，支持双指。我拿手指在板上划，红点跟着动，一眼就能看出这是块正经电容板。

**第三，滑条有两种人格。** 开关拨到 NORMAL 时，触摸条分左右两半，模拟左右 3D 摇杆，报的是**绝对位置**；拨到 ARCADE 时，报的是**从中线起算的相对滑动**——数值会乱跳，因为它记录的是"你往哪边划了一下"，而不是"你的手指在哪"。这个差异我一开始当成噪声，后来才想明白：街机 DIVA 的滑条本来就是手势判定。

顺便测了个数：这个设备报点 **250 Hz**，也就是 4 毫秒一帧。而原版 DS4 有线是 1000 Hz。对音游来说，这 3 毫秒的差距是实打实的。

## 六、既然改不了固件，那就改中间层

固件改不了，协议又全摸清了，那就只剩一条路：**在用户态做个中间层**，把 HID 报文读出来，重新翻译成别的东西。

架构很简单：

```
手台 ──USB HID──> 中间层 ──┬──> 键盘事件
                          └──> 虚拟 Xbox 手柄（Windows）
```

读报文这层，macOS 用 `hidapi` 就够了。Windows 上倒是踩了个大坑：`hidapi` 在 Python 3.15 上没有现成的 wheel，只能源码编译，然后 MSVC 链接器甩出一句 `LNK1104: 无法打开文件 .exp`。

排查下来是构建路径太长。但与其继续跟编译器搏斗，我干脆换了个思路：**用 ctypes 直接调 Win32 的 HID API**，这样 Windows 上连编译都不需要了。结果又踩了第二个坑——`SP_DEVICE_INTERFACE_DETAIL_DATA_W` 里的 `DevicePath` 声明为 `WCHAR * 1`，ctypes 访问这个字段时**只读一个字符**，于是每个设备路径都变成了 `\`，枚举结果永远是 0。

这两个坑加起来，差不多耗掉了一个小时。

界面做成了网页，本地起一个小服务，浏览器打开就能用：

- 手台实物布局，按下去会实时高亮
- 触摸板上的触点跟着手指走
- 点任意控件，按一下键盘就完成绑定
- 输出可选「键盘」或「XInput」

「XInput」这条路要装 ViGEmBus 驱动，装完游戏就能看到一个**真的 Xbox 360 手柄**，摇杆和扳机都是模拟量，不再有"合成按键被游戏过滤"的问题。面键还做了三套预设：Xbox 位置、Switch Pro 位置、PS 语义（圈=确认→A），也可以逐键自定义。

还有一个设计我特意加了：**「启用映射」必须手动点，且每次启动都重置回关闭。** 因为未启用时界面照样实时显示手台状态，你很容易误以为它已经在工作了——这种"看不见的开关"最坑人，所以我给它配了一条横幅、一个徽章、一个呼吸灯按钮，三处同步。

代码是 AI 辅助写的，能用，但我不对质量做任何保证，仓库 README 里也写清楚了。

## 七、一百块买到的东西

折腾完回头看，这一百块买到的其实不是一台"手台"。

它是一份**反面教材**：共用模具、固件写死模式、借别人的 VID 导致所有标准工具都不认、机身上还留着一个只供电不传数据的残废接口。这台机器把这个行业里能偷的懒，几乎全偷了一遍。

但它也是一份**正面教材**：正因为什么都改不了，我才把 HID 报文层从描述符到字节布局完整地拆了一遍。现在我知道它们在一个真实设备上长什么样，也知道一个偷懒的固件会在哪里露馅。

如果真要总结一条给自研的话，我觉得是这个：**固件别把功能写死，务必给上位机留出自定义的空间。**

这台手台最要命的不是便宜，而是它把一切都焊死了——模式编译期固定、按键映射写死、厂商接口是个空壳。用户想改一个键，只能像我这样在操作系统层面绕一大圈。

以后自己做手台，哪怕固件只实现最基本的功能，也要留一条能读写的配置通道（一个 Feature Report 或者一个简单的串口协议都行），让上位机能定义键位、灯效、滑条曲线。这样硬件卖出去了，玩法还能继续长。

我买它的初衷，本来也是想学架构、以后自己搓手台玩。从这个角度说，这一百块花得挺值——它把"该怎么做"和"不该怎么做"同时演示了一遍。

工具开源在这里，macOS 和 Windows 都能跑：

https://github.com/wujx3433/PG-P4016-Translator

如果你也在小黄鱼上捡到了同款，祝你玩得开心。
